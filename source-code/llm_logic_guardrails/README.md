# LLM Logic Guardrails in Prolog

This project demonstrates **Logic-based Guardrails** for validating Large Language Model (LLM) responses using symbolic logic rules in Prolog.

## Why This Project is Useful
Large Language Models (LLMs) are powerful but prone to hallucinations, logical inconsistencies, and safety policy violations. In applications requiring high reliability (e.g., financial advice, medical decisions, legal compliance), we cannot show raw LLM output to users without validation.

**Logic-based Guardrails** implement a neuro-symbolic pattern:
1. The LLM generates a structured response (e.g., JSON).
2. The JSON is sent to a **Prolog symbolic engine** where strict business rules and safety policies are defined.
3. Prolog checks if the generated content violates any constraints and returns a list of specific policy errors.
4. If errors are found, the output is rejected (or sent back to the LLM for self-correction).

This approach provides **mathematical guarantees of compliance** that are impossible to achieve with LLMs alone.

In this example, we validate a financial portfolio recommendation generated by an LLM against rules governing age limits, risk tolerances, asset boundaries, and arithmetic sums.

## Tools & Libraries Used
- **SWI-Prolog**: Performs the symbolic policy check using its JSON parsing and logic query engine.
- **Python (managed via `uv`)**: The application wrapper that interfaces with the LLM and calls Prolog.
- **Janus (`janus-swi`)**: The high-performance, bidirectional Python-Prolog bridge.

## How to Run the Example

Ensure `uv` is installed, then run the Python validation script:

```bash
uv run verify_llm.py
```

### Expected Output
The script runs two simulated LLM recommendations through the Prolog guardrails and prints the results (asserted programmatically; the script exits with code 1 if a check fails). Note: the rules genuinely fire — the risk-tolerance comparison is canonicalised so it works whether JSON string values arrive as Prolog atoms (`json_read_dict/2` default) or as strings (Janus):
